The Git client that keeps up.

Coral lays out every one of the Linux kernel's 1.48 million commits in about 6.2 seconds, holds them in under 300 MB, and sits at zero CPU when you stop. Rust engine, the system's own web view, no Electron.

Features

All of Git, in one window you can see through.

Every branch in its own lane, every change one click from staged, and an undo for the moments Git usually punishes.

A graph that holds a million commits.

The graph is drawn on a canvas from a compact store of rows, so the kernel's whole history scrolls as smoothly as a repository of ten commits.

  • Solo a branch or hide one; Coral remembers it per repository
  • Find any commit by message, author, path or id
  • Authors' pictures from Gravatar or GitHub, or their initials
  • Drag one branch label onto another to merge, push or pull

Find what the code said, not only the message.

The find box searches what each commit changed as well as what it says about itself. code:render_row finds the commits that added or removed it, whatever their messages claim, and after: and before: bound it by date.

  • code:"/fn [a-z_]+_row/" for a regular expression
  • Dates as 2026-05-01 or 2.weeks
  • A new search stops the one still running, so typing stays quick on the kernel

Find the commit that broke it.

Mark a commit bad and one that was good, and Coral checks out the one halfway between. Say whether it is good or bad, or skip it, and it halves again until one commit is left, named at the top of the list.

  • Every verdict marked on its row
  • Picks up a bisect started in the terminal, in its own terms
  • End it to go back to where you were

Interactive rebase, planned in a list.

Pick, reword, edit, squash, fixup, drop and reorder from one list, then start when it is right. If Git stops part-way, continue, skip or abort from the same place.

  • Merge, rebase, cherry-pick, revert and reset
  • Force pushes are always --force-with-lease
  • Patches out and in

Stage the line you mean.

Read the diff inline or side by side, with the changed words marked, then stage a file, a hunk or a single line.

  • Commit, amend and discard
  • Commit signing, per repository
  • Blame and file history for any line

Images, before and after.

A changed image is drawn rather than called binary: the two versions side by side, each with its size in pixels and bytes, on a checkerboard so transparency shows.

  • PNG, JPEG, GIF, WebP, BMP, ICO and AVIF
  • In a commit, a comparison, or what you are about to commit

Conflicts, with both sides named.

A three-pane merge tool shows your side and theirs, each named after the branch it came from, with the result underneath. Take a line, a block or a whole side.

  • Continue or abort a merge, rebase or cherry-pick at any step
  • Large and LFS files handled without loading them whole
  • Undo and redo for every operation

Keys at your fingertips.

A command palette on Ctrl P reaches every action, and a terminal opens on Ctrl ` in the repository you are looking at. Every shortcut can be rebound.

GitHub and GitLab

Pull and merge requests in the sidebar, and a new one opened from the branch you are on, drafts included. Enterprise and self-hosted too.

Checks at a glance

Each open pull or merge request is marked passing, failing or running, from GitHub's checks or GitLab's pipeline. One click opens the check that failed.

Updates itself

Install a new release from About, checked against Coral's signing key before anything is replaced. It only looks when you ask, or at launch if you turn that on.

Profiles

Work and personal, each with its own tabs, identity, ssh key and signing, so a commit never goes out under the wrong name.

Tokens in the keyring

Host tokens live in the operating system's keyring, and Coral answers git's credential requests itself.

Worktrees, stashes, submodules

Stash one file, or only what is staged. Plus shallow and blobless clones and SHA-256 repositories, and a window that refreshes as files change on disk.

Light and dark

Two themes drawn from the same set of colour tokens, so dark is designed rather than inverted. Switch from the title bar or the palette.

Tabs that stay

One tab per repository, grouped and coloured the way you like, restored on the next launch.

A command line, too

Fifty-four commands over the same engine as the window, each with a --json output for scripts.

Performance

Measured on the Linux kernel.

1,481,528 commits, 944 tags and a 96,000-file working tree: the repository that makes most clients wait. Coral's engine is Rust, its window is the system's own web view, and git is the one already on your computer.

6.2 sfrom launch to all 1,481,528 commits laid out
283 MBof memory with the whole kernel graph loaded
0%CPU while the window sits idle
90 msto check the status of all 96,025 files

Time until the window is still

Seconds from launch to the last repaint. Coral's includes ordering the whole history; the others load it as you scroll.

MB on disk. Coral uses the system's web view rather than bundling one.

How this was measured. Measured on 2026-10-21 on an Intel Core Ultra 9 285H, 16 threads with 64 GB of memory, running Ubuntu 24.04.5, Linux 6.17 and git 2.43.0. Each client opened the same local clone of the Linux kernel, alone on a nested X display, from a fresh profile, three times; the medians are shown. Memory is the proportional set size of all the client's processes twenty seconds after the window stopped changing. Status is the coral status command, warm, process start included.

Coral 1.2.4. Measured again on 2026-10-22, beside 1.2.2 on the same machine the same day, it came out the same: 6.0 s against 6.0 s to still, 372 MB against 370 MB of memory, and no CPU at idle for either. Both used more memory that day than 1.2.2 did on the 21st, so the change is the day's, not the code's; the comparison above stays the one where every client was measured together.

The script and every run's numbers are in the repository: tests/clients. Fork and Sourcetree have no Linux build and SmartGit was left out because its setup requires agreeing to its licence, so none of them were measured.
